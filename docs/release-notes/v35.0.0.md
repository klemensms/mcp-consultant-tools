## Overview

v35 is a **security-hardening** release. It closes the gaps deferred from the v34 audit: it gives MCP client harnesses the metadata to gate destructive operations, adds automated dependency-vulnerability surfacing to CI, and hardens the `rest-api` package's OpenAPI fetch and TLS-verification handling. No new required configuration; existing `.mcp.json` configs keep working unchanged.

## Highlights

- **Every tool now carries MCP safety annotations** (`readOnlyHint` / `destructiveHint` / `openWorldHint`) — 589 tools across 21 packages — so clients can confirm before destructive operations and run read-only tools without friction.
- **Automated dependency-vulnerability surfacing** via Dependabot + an `npm audit` CI gate (previously zero automated detection).
- **`rest-api` hardening:** the OpenAPI-spec fetch is now bounded (scheme guard, no redirects, size cap) and the SSL-verification toggle no longer behaves misleadingly.

## 🚀 New Features

- **MCP tool safety annotations across all packages.** All 589 tools in the 21 integration packages now declare `readOnlyHint`, `destructiveHint`, and (where they reach an external service) `openWorldHint`. Destructive operations (`delete-*`, `drop`, `deactivate-*`, arbitrary SQL/Dataverse executors, queue purges, access revocations, PR-merge-with-branch-delete, etc.) are marked so a client harness can prompt for confirmation; pure reads are marked so they run without friction. Annotations are advisory metadata — they change no tool behaviour or output shape.

## 🛠 DevOps, Pipelines & Infrastructure

- **Dependabot** (`.github/dependabot.yml`) opens grouped PRs for vulnerable/outdated npm dependencies and GitHub Actions, weekly.
- **`npm audit` CI gate** (`build.yml`) fails the build on high/critical advisories (lower-severity findings are surfaced but don't block). Whether a failure blocks merges is governed by branch protection.

## 🔧 Technical Improvements / Architecture

- **`rest-api` OpenAPI-spec fetch is now bounded** (`doFetchOpenApiSpec`): rejects non-`http(s)` spec URLs (e.g. `file://`), never follows redirects (`redirect: "error"`), and caps the response at 10 MB (Content-Length pre-check + post-read byte check) to guard against memory exhaustion. This brings the spec-fetch path in line with the main request path's v34 hardening.

## 🐛 Bug Fixes

- **`rest-api` SSL-verification toggle was a silent no-op.** `REST_ENABLE_SSL_VERIFY=false` created an `https.Agent` that native `fetch` ignores, so TLS was always verified regardless of the setting. The misleading dead agent is removed. The server now **never disables TLS on the operator's behalf**; if `REST_ENABLE_SSL_VERIFY=false` is set it emits a loud security warning and directs the operator to set `NODE_TLS_REJECT_UNAUTHORIZED` in the environment themselves if they genuinely must (keeping the insecure scope explicit at deploy time). Default behaviour (verification on) is unchanged.
- **`todoist` was missing from the root TypeScript project references**, so `tsc --build` never built it (it built only via direct `--workspace` calls). Added to `tsconfig.json` references so the clean release build includes it.

## Verified

- Full clean build (`npm run build:release`) compiles all 24 packages with zero errors; every published package ships `.d.ts` types.
- Annotation completeness: 589 tool registrations = 589 annotations across all packages.
- Annotations confirmed live in `tools/list` for `rest-api` and `azure-sql` (read-only vs destructive serialise correctly).
- `rest-api`: `file://` OpenAPI URL rejected before any fetch; SSL-disabled warning fires on first use.
