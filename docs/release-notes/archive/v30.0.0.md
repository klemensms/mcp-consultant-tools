# Release Notes: v30.0.0

**Release Date:** 2026-04-27
**Branch:** `release/30.0`
**Type:** Major release

## Overview

v30.0.0 lands four major themes:

1. **Native 1Password integration** — every package can now resolve `op://` references in env vars at startup via the `1password` CLI, removing the need for plaintext secrets in `.mcp.json` files.
2. **Azure DevOps work-item sync rewrite** — sync is now annotation-driven and fully dynamic. Any field on any work-item type can round-trip without a code change. Image attachments are first-class citizens. Three long-standing silent-data-loss bugs are fixed.
3. **PowerPlatform customization expansion** — Field Security Profiles (14 tools), source-control-friendly form-file workflow (3 tools), and Quick Find view guard.
4. **Azure Management write tools** — App Service log retrieval, lifecycle management, and config updates.

Plus a new (scaffold-only) `todoist` package, CLI install scripts for all packages, and a long list of reliability fixes across the Azure DevOps and Azure SQL servers.

## Breaking Changes

### Azure DevOps

- **`queue-build` parameter renamed.** `branch` → `sourceBranch` to match ADO's REST contract. CLI flag `--branch` unchanged.
- **`check-work-item-markdown` output reshaped.** The four fixed keys (`howToTest`, `predeploymentSteps`, `predeploymentInfo`, `postdeploymentInfo`) are replaced with a single `customBodyFields: Record<refname, "markdown" | "html" | "not_present">` map.
- **Removed env vars** (use template overrides instead): `AZUREDEVOPS_SYNC_FIELD_HOW_TO_TEST`, `AZUREDEVOPS_SYNC_FIELD_DEPLOYMENT_INFO`, `AZUREDEVOPS_SYNC_FIELD_PREDEPLOY`, `AZUREDEVOPS_SYNC_FIELD_POSTDEPLOY`. Legacy files referencing these fields still parse correctly via the legacy-heading fallback.
- **`getAdditionalFieldConfig` and `AdditionalFieldConfig` removed** from `@mcp-consultant-tools/azure-devops` public exports.
- **Bug work items now correctly sync `Microsoft.VSTS.TCM.ReproSteps`.** Pre-beta.18 the sync silently wrote bug body content to `System.Description`. Re-pull any synced bugs after upgrade to move content to the correct field.
- **`ParsedWorkItemFile` / `ParsedNewWorkItemFile`** gain `reproSteps`, `fieldMap`, `bodyFieldMap`, `localOnlySections`, `workItemType`. Downstream consumers constructing these manually must update.

No other breaking changes.

## New Features

### 1Password CLI Secret Resolution (all packages)

Every MCP server and CLI now resolves `op://Vault/Item/field` references in env vars at startup via the `1password` CLI. Lets you store credentials in 1Password and reference them in `.mcp.json` instead of pasting plaintext. 1Password config is now the **primary documented example** in all package docs. Includes an agent prompt for upgrading existing `.mcp.json` files to use 1Password references.

### CLI Install Scripts

New install scripts scaffold a global CLI install for every package. Bash 3.2 compatible. Includes a CLI setup guide.

### Azure Management — App Service Tools (5 new + 1 enhancement)

| Tool | Description |
|------|-------------|
| `get-app-service-logs` | Fetch logs via Kudu SCM API — Docker container logs (Linux), eventlog.xml (Windows), stdout. Auto-detects OS. |
| `restart-app-service` | Restart an App Service. Requires `AZURE_MGMT_ENABLE_WRITE=true`. |
| `stop-app-service` | Stop a running App Service. Reports previous state. |
| `start-app-service` | Start a stopped App Service. Reports previous state. |
| `set-app-service-config` | Update app settings or connection strings using safe merge pattern (GET → merge → PUT). Supports `removeSettings` for key deletion. |

`get-app-service` gains a `showValues` parameter that overrides `AZURE_REDACT_SECRETS` for a single call.

New env var `AZURE_MGMT_ENABLE_WRITE` gates all write operations. Required Azure permission: `Website Contributor`.

### Azure DevOps — Test Management (7 new tools)

New `test` domain — automated test run management via ADO's `_apis/test/` endpoint (Basic license, no Test Plans extension needed):

- **Lifecycle:** `create-test-run`, `add-test-results`, `complete-test-run`
- **Query:** `get-test-runs`, `get-test-run-results`, `get-test-case-history`
- **Linking:** `link-test-case` (idempotent test case ↔ story / ↔ run linking)

Enables full agent-driven testing workflow: implement → test → record → link → review.

### Azure DevOps — Work Item Image Sync

Work item attachments (images embedded in Description, Repro Steps, Acceptance Criteria, custom HTML fields, and comments) are now first-class:

- **Pull** downloads attachments to `{syncFolder}/{workItemId}/attachments/{guid}-{filename}`, rewrites `<img src>` to local paths so any markdown viewer renders inline, and writes a `.attachments.json` manifest.
- **Push** resolves manifest entries — known attachments rewrite back to ADO URLs (no upload), new local files upload via `_apis/wit/attachments`. Removed `<img>` refs simply don't appear in pushed HTML; ADO attachments are never auto-deleted.
- New standalone tool **`upload-work-item-attachment`** for arbitrary file uploads (e.g. Playwright screenshots) with optional `workItemId` to register in that item's manifest.
- `Microsoft.VSTS.TCM.ReproSteps` is now a synced body section with HTML→markdown auto-conversion.

Bundled bug fixes:
- `emptyDiv` Turndown rule no longer destroys images during HTML→markdown conversion (latent bug; affected ALL existing auto-conversion flows).
- Duplicate `?fileName=` query params on uploaded URLs eliminated.
- No-op round-trip push responses now include image stats.

### Azure DevOps — Dynamic Annotation-Driven Sync

The sync pipeline is fully dynamic — any text or scalar field on any work-item type can round-trip without a code change. Two mechanisms:

1. **Scalar fields → frontmatter keys** (using ADO reference names like `Custom.ConsultancyProcess`, with an alias table for the 12 most common fields).
2. **Long-text fields → annotated body sections:**
   ```markdown
   ## Agentic Data
   <!-- ado-field: Custom.AgenticData -->

   Body content here.
   ```

Per-type built-in templates ship with the package (User Story, Bug, Task, Feature, Epic). Override via `MCP_ADO_SYNC_TEMPLATE_DIR`. Custom fields surface automatically in pulled files (short scalars in frontmatter, long-form as auto-annotated body sections).

### PowerPlatform Customization — Field Security Profiles (14 new tools)

End-to-end FSP management for GDPR / sensitive data scenarios:

- **Secured column flag:** `set-column-secured`, `set-columns-secured` (batch)
- **FSP lifecycle:** `create-field-security-profile`, `update-field-security-profile`, `delete-field-security-profile`, `list-field-security-profiles`, `get-field-security-profile` (one-call snapshot with permissions, teams, users)
- **Field permissions:** `add-field-permission`, `add-field-permissions` (batch), `remove-field-permission`
- **Assignments:** `assign-fsp-to-team` / `unassign-fsp-from-team`, `assign-fsp-to-user` / `unassign-fsp-from-user`

`powerplatform` (read-only) gains 3 mirror tools: `list-field-security-profiles`, `get-field-security-profile`, `get-secured-columns` (audit helper showing FSP coverage per secured column on an entity).

Tool counts: `powerplatform-customization` 71 → 85, `powerplatform` 46 → 49. Backed by a new shared `FieldSecurityService` in `powerplatform-core`.

### PowerPlatform Customization — Form File Workflow (3 new tools)

Source-control-friendly tooling for Dataverse form edits, mirroring the `deploy-web-resource-file` pattern:

- **`download-form-to-file`** — Fetch a form's XML to a local file, verbatim (no parser round-trip). Writes a sidecar `.meta.json` (formId, versionNumber, name, formType, downloadedAt) and a timestamped snapshot under `<filePath>.history/`.
- **`deploy-form-file`** — PATCH local form XML bytes verbatim to Dataverse. Resolves `formId` from sidecar. Supports `expectedVersionNumber` for optimistic concurrency. Writes upload snapshots to history.
- **`diff-form-file`** — Read-only comparison against the current remote form. Returns byte-identical status, sizes, and version numbers.

XML bytes are never round-tripped through a parser — whitespace, attribute order, and self-closing tag style are preserved so diffs stay clean. History directory is append-only.

Tool count: `powerplatform-customization` 85 → 88.

### Azure DevOps — Iteration Path / Area Path on Task Sync

Task sync now supports `Iteration Path` and `Area Path` fields for round-trip editing.

## Bug Fixes

### Azure DevOps

- **Sync no longer truncates fields containing inner `##` headings** (silent data loss). A `##` line is now a section boundary only when followed by `<!-- ado-field: REFNAME -->`. Other `##` lines are preserved as content of the enclosing annotated section.
- **Task Description truncation at `---`** (silent data loss). The block-boundary regex no longer treats intra-Description horizontal rules as inter-task separators. Tasks are delimited only by the next `## Task` / `## NEW TASK` heading.
- **`TF401320 InvalidNotEmpty` when closing a task with Remaining Work = 0**. Transitions to terminal states (Closed, Done, Resolved, Removed, Completed) now emit a `remove` patch for Remaining Work instead of `value: 0`.
- **`_Description is HTML format - not displayed_` placeholder leaked into task files**. Replaced with a local `htmlToMarkdown()` fallback so descriptions always serialize as markdown.
- **MCP harness param coercion** (blocker). `zCoerceNumber` and `zCoerceNumberArray` schema helpers accept stringified numbers (`"1351"`) and stringified arrays (`"[1351]"`). Fixes every ID-parameter tool against harnesses that serialize all values as strings.
- **Push `state` field included** in `sync-work-item-from-file`.
- **302 auth redirects detected** instead of returning empty data.
- **Image capture** moved to bundled code with selection-copy fallback; clipboard operations now work in sandboxed MCP App iframe; buttons hidden in capture; `visualize-data` usage restricted.

### Azure DevOps Admin

- **`queue-build` silently ignored `sourceBranch`**. Schema parameter renamed from `branch` to `sourceBranch`. Also adds `sourceVersion` (commit SHA) for pinning to a specific commit. **Breaking** — see Breaking Changes.
- **`cancel-build` returned HTTP 415**. The ADO build update endpoint expects plain JSON, not JSON Patch. `cancelBuild` now overrides content type to `application/json`.

### Azure SQL

- **`sql-deploy-view-file` and `sql-deploy-sproc-file` strip `GO` batch separators** before executing. The mssql/tedious driver doesn't understand `GO` (it's a client-tool directive). Files ending with `GO` previously failed with "Incorrect syntax near 'GO'". Handles `GO`, `go`, `Go` with optional whitespace and multiple occurrences.

### PowerPlatform

- **`update-view` on Quick Find savedqueries** (`querytype = 4`) now fails fast with a specific error naming which fields are rejected and the maker-portal workaround. Previously, `name`/`layoutxml`/`layoutjson` PATCHes returned 204 success while being silently discarded by Dataverse, and `fetchxml` 400'd with a generic error. `description` and `isdefault` PATCHes still pass through.
- **`check-dependencies` 404 fixed**; `check-delete-eligibility` no longer produces contradictory output.
- **Web resource tool descriptions** updated to prefer `deploy-web-resource-file` over inline `update-web-resource`.

## Migration Notes

**Azure DevOps sync users:**

1. Existing files without `<!-- ado-field: X -->` annotations parse correctly via the legacy heading fallback. Pull any file once and it's rewritten in the new annotated format.
2. **Bug files using `# Description` for what is logically repro steps are auto-routed to `Microsoft.VSTS.TCM.ReproSteps` on parse**. The fix applies retroactively — re-pull bugs after upgrade.
3. If you used `AZUREDEVOPS_SYNC_FIELD_*` env vars, replace them with template overrides via `MCP_ADO_SYNC_TEMPLATE_DIR`.
4. Callers of `queue-build` (azure-devops-admin) using `branch` parameter must update to `sourceBranch`. CLI `--branch` flag is unchanged.

**1Password adopters:**

The new `op://` resolver is opt-in. Existing plaintext env vars in `.mcp.json` continue to work unchanged. To migrate, see the upgrade-to-1Password agent prompt in the docs.
