# Release Notes: v31.0.0-beta.5

**Date:** 2026-05-16
**Branch:** `release/31.0`
**Status:** Held for npm publish

> Per-iteration agent-level detail. The user-facing single source of truth is [`v31.0.0.md`](v31.0.0.md).

## Overview

Adds a new MCP package — `@mcp-consultant-tools/fabric` — for Microsoft Fabric (workspaces, capacities, items, OneLake shortcuts, governance domains, tenant-wide admin inventory). No breaking changes; existing servers and configs are untouched. The meta package re-publishes (beta.4 → beta.5) only to pick up the new fabric registration in its bundled startup.

This iteration is **independent of the v32.0.0-beta.2 PII/audit work**, which is still held for publish on the same branch. Fabric publishes on the existing v31 train (`31.0.0-beta.4` baseline) and does not depend on or require any of the v32 changes.

## Changes Implemented

### New package — `@mcp-consultant-tools/fabric@31.0.0-beta.4` (first publish)

MCP server binary `mcp-fabric` plus companion CLI `mcp-fabric-cli`. Mirrors the `azure-devops` sibling pattern: layered `services/` → `tools/` → `cli/commands/`, shared `ServiceContext` via `context-factory.ts`, every MCP tool has a 1:1 domain-grouped CLI command.

**Surface — 27 tools across 6 domains:**

| Domain | Tools | API |
|--------|-------|-----|
| Workspaces | `fabric-list-workspaces`, `fabric-get-workspace`, `fabric-create-workspace`, `fabric-update-workspace`, `fabric-delete-workspace`, `fabric-list-workspace-role-assignments`, `fabric-add-workspace-role-assignment`, `fabric-remove-workspace-role-assignment` | core `/v1` |
| Capacities | `fabric-list-capacities`, `fabric-get-capacity`, `fabric-assign-workspace-to-capacity`, `fabric-unassign-workspace-from-capacity` | core `/v1` |
| Items | `fabric-list-items`, `fabric-get-item`, `fabric-create-item`, `fabric-update-item`, `fabric-delete-item`, `fabric-create-lakehouse`, `fabric-create-warehouse`, `fabric-create-notebook` | core `/v1` |
| Shortcuts | `fabric-list-shortcuts`, `fabric-create-shortcut`, `fabric-delete-shortcut` | core `/v1` |
| Domains | `fabric-list-domains`, `fabric-get-domain`, `fabric-assign-domain-workspaces`, `fabric-unassign-domain-workspaces` | admin `/v1/admin` |
| Admin | `fabric-admin-list-workspaces`, `fabric-admin-list-items`, `fabric-admin-get-tenant-settings` | admin `/v1/admin` |

Plus 2 prompts (`fabric-workspace-overview`, `fabric-tenant-inventory`) and the CLI's domain-grouped command tree (`workspace`, `capacity`, `item`, `shortcut`, `domain`, `admin`).

**Authentication:** Azure AD (Entra) service principal via `@azure/identity` `ClientSecretCredential`. Single token scope — `https://api.fabric.microsoft.com/.default` — covers both the core API and the admin API. Token cached in-memory with a 5-minute refresh buffer.

**`FabricClient`** (axios wrapper) handles both base URLs (`/v1` core, `/v1/admin`), auto-paginates `value` + `continuationToken` collections via `listAll()`, surfaces HTTP 202 long-running-operation responses as `{ accepted: true, status: 202, location, retryAfter }`, and maps 401/403/404/429 to friendly error messages with hints about Fabric admin rights / tenant-setting opt-in for admin routes.

**Write-protection:** mutations are disabled by default and gated behind two feature flags — `FABRIC_ENABLE_WRITE` covers all create/update/assign operations, `FABRIC_ENABLE_DELETE` independently covers deletion of workspaces, items, and shortcuts. The same gate pattern as `sharepoint` and `azure-devops`.

**Env-var prefix:** `FABRIC_*` to match the sibling-package convention (`SHAREPOINT_*`, `AZUREDEVOPS_*`, `TEAMS_*`) rather than the cross-repo `MCP_FABRIC_*` contract. Flagged explicitly in `packages/fabric/CLAUDE.md`.

## Testing

- **Workspace `npm run build`:** clean across all 24 packages (fabric is the new 24th workspace).
- **CLI surface verification:** `mcp-fabric-cli --help` renders the 6 top-level domain commands and global flags. Each domain `--help` (`workspace`, `capacity`, `item`, `shortcut`, `domain`, `admin`) lists its subcommands with correct argument/option signatures.
- **Auth-error path:** `mcp-fabric-cli workspace list` with no `FABRIC_*` env vars set returns the expected `Missing Microsoft Fabric authentication. Required variables: FABRIC_TENANT_ID, FABRIC_CLIENT_ID, FABRIC_CLIENT_SECRET. Provide a service principal (Azure AD app registration) with access to the Fabric APIs.` error and exits cleanly.
- **NOT exercised against a live Fabric tenant.** Every endpoint path, payload shape, response envelope, and pagination behaviour is derived from the Fabric REST API documentation and the established sibling-package patterns — none are confirmed against an actual Fabric API call. This beta IS the live-environment test vehicle.

## Known Issues

- **Fabric admin / domain calls require a tenant-setting opt-in.** The `domain` and `admin` tools (`fabric-list-domains`, `fabric-get-domain`, `fabric-assign-domain-workspaces`, `fabric-unassign-domain-workspaces`, `fabric-admin-*`) hit `/v1/admin`. In a tenant where "Service principals can use Fabric APIs" is enabled but the admin-API tenant-setting opt-in for service principals is NOT, these calls return `403`. The 403 mapping in `FabricClient.request()` includes a hint pointing at this. Not a code defect — documented in `packages/fabric/CLAUDE.md` and `docs/documentation/FABRIC.md`.
- **`fabric-get-capacity` filters the list endpoint client-side** because the Fabric REST API has no per-capacity GET route. The service throws `Capacity not found: {id}` if the ID isn't in the list. Documented in `docs/technical/FABRIC_TECHNICAL.md` ("Implementation Details").
- **No `mcp-local-tester` evidence in this beta.** Live-tenant verification is the purpose of the beta cycle.
