# Release Notes: v32.0.0-beta.4

**Date:** 2026-06-02
**Branch:** `release/31.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v32.0.0.md`](v32.0.0.md).

## Overview

Version-reporting fix. The only functional change is in `@mcp-consultant-tools/core`: the CLI `--version` and the MCP server's reported version now derive from the running package's `package.json` instead of hardcoded strings. No tool behaviour, schema, return shape, or env-var surface changed — every package behaves identically to `32.0.0-beta.3`.

> **No breaking changes — drop-in upgrade.** Configs that pin any `32.0.0-beta.3` package can bump to `32.0.0-beta.4` without touching `.mcp.json`.

## Changes Implemented

- **CLI `--version` derives from `package.json`** (`core/src/helpers/cli-helpers.ts`). `createCliProgram` now calls a shared `resolvePackageVersion()` that walks up from `process.argv[1]` to the running package's `package.json`, falling back to the passed `opts.version` only if resolution fails. Previously every package's `cli.ts` passed a hardcoded version that the release version bump (which only seds `package.json`) never updated — so `--version` mis-reported across the whole suite (e.g. `27.0.0`, `28.0.0-beta.8`, `32.0.0-beta.1`). The 20 `cli.ts` call sites are untouched; their hardcoded values are now fallbacks.
- **MCP server version derives from `package.json`** (`core/src/helpers/mcp-helpers.ts`). `createMcpServer` uses the same `resolvePackageVersion()` helper, so the version reported in the MCP `initialize` handshake is correct instead of the hardcoded `'1.0.0'` carried in every `index.ts`.
- **New shared helper** `core/src/helpers/resolve-version.ts` (`resolvePackageVersion(fallback)`), used by both `createCliProgram` and `createMcpServer`.
- **Lockstep bump to `32.0.0-beta.4`** across all 24 suite packages; inter-package `@mcp-consultant-tools/*` deps repinned. `@mcp-consultant-tools/audit-cli` stays on its `0.1.0` track (its `core` dep repinned to `32.0.0-beta.4`).

## Testing

- `packages/core` test suite: **80/80 passing**.
- `npm run build`: clean across all 24 packages.
- CLI `--version` verified: `powerplatform-data` and `azure-devops` CLIs both report `32.0.0-beta.4` (resolved from `package.json`, not the stale hardcoded strings).
- Server-context version resolution verified from a script invoked inside a package `build/` directory → `32.0.0-beta.4`.
- PII redaction re-verified live on the `beta` channel after a clean reconnect: `pii-demo-5` (`PII_PROTECTION=true`) redacts contact email/phone/name with footer; `pii-demo-1` (`PII_PROTECTION` off) returns cleartext.

## Known Issues

- The diagnosis of this iteration was complicated by stale **globally-installed** `@mcp-consultant-tools/*` packages shadowing `npx …@beta` on the maintainer's machine — an environment issue, not a package defect. If `--version` or behaviour looks stale after upgrading, ensure no old global install is on `PATH` (`npm ls -g | grep mcp-consultant-tools`) and clear the npx cache.
- No new product issues this iteration. Carry-over items from the v32 line are tracked in [`v32.0.0.md`](v32.0.0.md) and earlier per-iteration files.
