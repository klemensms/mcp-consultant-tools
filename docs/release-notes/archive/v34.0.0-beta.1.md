# Release Notes: v34.0.0-beta.1

**Date:** 2026-06-12
**Branch:** `release/34.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v34.0.0.md`](v34.0.0.md).

## Overview

Initial v34 beta. Fixes GitHub issues [#1](https://github.com/klemensms/mcp-consultant-tools/issues/1) (log-analytics timespan clipping), [#2](https://github.com/klemensms/mcp-consultant-tools/issues/2) (wiki subPages never populated), the PowerPlatform picklist option-set omission, and [#3](https://github.com/klemensms/mcp-consultant-tools/issues/3) (release-pipeline hardening). Selective beta: 7 packages bumped to 34.0.0-beta.1; all other packages unchanged at 33.0.0 (`core` included — no functional change, no bump).

## Changes Implemented

- `82738fe` fix(powerplatform-core): `MetadataService.getEntityAttribute` — strip `#` from `@odata.type` before the picklist-type check (the check never matched, so option values were never fetched); on `$expand=OptionSet` failure or empty expansion, fall back to attribute-scoped `OptionSet` then `GlobalOptionSet` navigation-property reads; set `optionSetWarning` on the response when all lookups fail. Added vitest infra + 5 tests (first tests in this package).
- `28254dc` fix(log-analytics): timespan resolution moved into `LogAnalyticsService.executeQuery` (shared by MCP + CLI). New `src/utils/timespan.ts` resolver: derive from widest `ago()` when no explicit timespan, `PT1H` only with no `ago()`, explicit timespan verbatim + `timespanWarning` when it clips. `QueryResult` gains `effectiveTimespan`/`timespanWarning` (additive). Markdown output + CLI summary echo them. CLI `query execute` dropped its `PT1H` Commander default. vitest infra + 13 tests.
- `b585b2d` feat(azure-devops): `getWikiPage`/`getWikiPageById` gain `recursionLevel` (`none`|`oneLevel`|`full`); `subPages` only included when requested, `subPagesNote` otherwise. New `getWikiPageTree` service method + `get-wiki-tree` MCP tool + `wiki tree` CLI command (slim path hierarchy + `pageCount`, no content). Tool counts: azure-devops 57→58 (64→65 with PR write). 5 wiki-service tests.
- `8a34c7f` chore(release): root `build:release` script (clean + build); both release workflow docs mandate it pre-publish; `scan-tarball.sh` fails on zero `.d.ts` when `types` is declared (conditional, mirrored verbatim to `mcp-computer-use` @ `799a663`).

## Testing

- Monorepo suite: 115 tests green (core 90, log-analytics 13, azure-devops 7, powerplatform-core 5).
- Live: picklist (`account/accountcategorycode`) + state (`account/statecode`) option values via `mcp-pp-cli` against the dedicated PowerPlatform test environment; wiki tree (329 pages) + `--recursion-level oneLevel` + default-annotation via `mcp-ado-cli` read-only against a real project wiki.
- Simulated the stale-`tsbuildinfo` no-declarations incident: incremental build reproduced it, `.d.ts` tarball gate caught it (exit 1), `build:release` resolved it.
- NOT verified live: Log Analytics fallback against a real workspace (no test workspace exists; API boundary covered by unit tests with mocked axios).

## Known Issues

- ADO's by-path wiki Pages API returns no numeric page ids even with `recursionLevel=full` — `get-wiki-tree` nodes are path-keyed; ids populate only where the API provides them.
