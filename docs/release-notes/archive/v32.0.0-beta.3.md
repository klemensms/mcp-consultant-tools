# Release Notes: v32.0.0-beta.3

**Date:** 2026-06-02
**Branch:** `release/31.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v32.0.0.md`](v32.0.0.md).

## Overview

Non-functional maintenance beta. No tool behaviour, schema, return shape, or env-var surface changed — every package behaves identically to `32.0.0-beta.2`. This iteration is a repository cleanliness pass plus a lockstep version unification so the whole suite ships at one coherent version ahead of the `32.0.0` promotion.

> **No breaking changes — drop-in upgrade.** Configs that pin any `31.x`/`32.0.0-beta.2` package can bump to `32.0.0-beta.3` without touching `.mcp.json`.

## Changes Implemented

- **Lockstep version unification.** Every suite package bumped to `32.0.0-beta.3` (previously asymmetric: most at `31.0.0-beta.4`, `meta` at `31.0.0-beta.5`, the PII/audit subset at `32.0.0-beta.2`). Inter-package `@mcp-consultant-tools/*` dependencies all repinned to `32.0.0-beta.3`. `@mcp-consultant-tools/audit-cli` stays on its independent `0.1.0` track (its `core` dep repinned to `32.0.0-beta.3`).
- **Repository cleanup (text-only, no logic changes).** Genericised example identifiers and product/company names in shippable tool/CLI descriptions and `.describe()` examples (e.g. product-name references in `log-analytics` and an example feed name in `azure-devops-admin`), a cosmetic publisher display-name default in `powerplatform-core`, and source comments. Removed internal planning/working documentation that is not part of the product. User-facing docs (`docs/documentation/*`, `docs/technical/*`) and all tool behaviour are unchanged.

## Testing

- `packages/core` test suite: **80/80 passing**.
- `npm run build`: clean across all 24 packages.
- `npm install`: lockfile re-synced cleanly against the unified versions.

## Known Issues

- None new this iteration. Carry-over items from the v32 line are tracked in [`v32.0.0.md`](v32.0.0.md) and the earlier per-iteration files.
