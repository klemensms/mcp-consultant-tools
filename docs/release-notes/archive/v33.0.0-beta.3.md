# Release Notes: v33.0.0-beta.3

**Date:** 2026-06-10
**Branch:** `release/33.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v33.0.0.md`](v33.0.0.md).

## Overview

Single-fix beta. `complete-test-run` always failed with `HTTP 415 (TF400898)` on the run-state PATCH, leaving automated test runs stuck "In Progress" even though `create-test-run` and `add-test-results` succeeded and saved their results. This iteration overrides the PATCH `Content-Type` for the Test Runs – Update call so ADO accepts it. Selective bump — only `azure-devops` moves to `33.0.0-beta.3`; `core` stays at `33.0.0-beta.1` and all other packages stay at `32.0.0`.

## Changes Implemented

- **fix(azure-devops): send `Content-Type: application/json` on the test-run state PATCH** (`src/services/test-service.ts`). The shared HTTP client (`azure-devops-client.ts`) defaults every PATCH to `Content-Type: application/json-patch+json` — correct for work-item updates, which send RFC 6902 JSON-Patch arrays. But the Test Runs – Update endpoint (`PATCH _apis/test/runs/{id}`) takes a plain JSON merge body (`{ state: 'Completed', comment }`), and ADO rejected the JSON-Patch media type with `415 (TF400898)`. `completeTestRun` now passes `{ 'Content-Type': 'application/json' }` as the `customHeaders` override — the same pattern `updateWorkItemComment` already uses for its plain-JSON PATCH. `create-test-run` / `add-test-results` were unaffected (they are POSTs, which already default to `application/json`). Verified the repo's other three `client.patch` sites are correct (one overrides; the two work-item updates legitimately send JSON-Patch arrays), so this was the only latent instance. The fix is at the service layer, so the matching `mcp-ado-cli test complete-run` CLI command is fixed in lockstep.
- **test(azure-devops): stood up vitest in the package + added a regression test.** Mirrored `core`'s vitest setup (`vitest.config.ts`, `test` script, `vitest` devDep) — the first tests in this package. `src/services/__tests__/test-service.test.ts` mocks axios and asserts `completeTestRun` PATCHes the run with `Content-Type: application/json` and a `{ state: 'Completed', comment }` merge body. Added `src/**/__tests__/**` to the package `tsconfig.json` exclude (matching `core`) so test files are not emitted into the published `build/` artifact.

This is pre-existing display behaviour, unrelated to the 415 fix, and out of scope for this iteration.
