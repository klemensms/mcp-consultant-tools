# Release Notes: v33.0.0-beta.4

**Date:** 2026-06-10
**Branch:** `release/33.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v33.0.0.md`](v33.0.0.md).

## Overview

Single-fix beta. Closes the display bug flagged as a known issue in beta.3: `complete-test-run` always reported `Passed: 0, Failed: 0` in its completion summary even when results passed. The persisted ADO data and `get-test-run-results` were always correct — only the completion summary was wrong. Selective bump — only `azure-devops` moves to `33.0.0-beta.4`; `core` stays at `33.0.0-beta.1` and all other packages stay at `32.0.0`.

## Changes Implemented

- **fix(azure-devops): aggregate `complete-test-run` pass/fail counts from per-result outcomes** (`src/services/test-service.ts`). `completeTestRun` read the `passedTests` / `unanalyzedTests` aggregates straight off the run-state PATCH response, but ADO recomputes those lazily for these Basic-license automated runs (`isAutomated: true`, no Test Plan), so they came back `0` — only `totalTests` was populated. The method now issues a follow-up `GET _apis/test/runs/{id}/results` after the PATCH and counts `outcome === 'Passed'` / `'Failed'` itself — the same approach `add-test-results` already uses — and derives `totalTests` from `results.length` for self-consistency. The return shape is unchanged, so the matching `mcp-ado-cli test complete-run` CLI command is fixed in lockstep with no CLI edit.
- **feat(azure-devops): `complete-test-run` summary now prints `Other: N`** (`src/tools/test-tools.ts`). With the corrected counts, runs containing `NotExecuted` / `NotApplicable` results (e.g. 4 Passed + 3 NotExecuted of 7) would otherwise show `Passed: 4, Failed: 0` against `Total: 7` and look inconsistent. The tool now appends `Other: {total − passed − failed}`, matching the existing `add-test-results` output.
- **test(azure-devops): regression test for the aggregation.** Updated the existing 415/Content-Type test to mock the new follow-up `GET` on the run results, and added a test asserting the counts come from the per-result outcomes (4 Passed / 3 NotExecuted / 0 Failed → `Total 7, Passed 4, Failed 0`) and **not** the PATCH response (which returns `passedTests: 0`).

## Version bump

- `azure-devops`: 33.0.0-beta.3 → 33.0.0-beta.4 (its `@mcp-consultant-tools/core` dependency pin stays at 33.0.0-beta.1 — core unchanged).
- All other packages: unchanged (`core` 33.0.0-beta.1; the rest 32.0.0).

## Testing

- Vitest: `test-service.test.ts` 2/2 green (`npm test --workspace=packages/azure-devops`). The new test reproduces the exact client scenario from the beta.3 known issue — PATCH returns `passedTests: 0`, the results GET returns 4 Passed / 3 NotExecuted — and asserts the corrected `Total 7 / Passed 4 / Failed 0`.
- `tsc` + `vite` build: pass.
- **No live ADO run created.** The `azure-devops` package has no test environment, and the throwaway run created during beta.3 testing could not be deleted via this toolset (no `delete-test-run` tool) — so a deterministic unit test reproducing the scenario was used in place of another undeletable live run.

## Known Issues

- None for this iteration. The beta.3 known issue (`passedTests` / `failedTests` reading `0` on completion) is resolved here.
