# Release Notes: v35.0.0-beta.4

**Date:** 2026-07-22
**Branch:** `release/35.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

Closes the last three capability gaps that the TSG Vantage assurance skills depended on from the
retiring predecessor toolset. All three are read-only additions to existing servers — no new
required environment variables, no changed return shapes, no removed tools. Drop-in upgrade.

## Changes Implemented

- **`azure-devops`: pull-request unified diff.** New `mcp-ado-cli pr diff <project> <repo> <prId>`
  with `--patch-only`, `--path <p...>`, `--context <n>` and `-i <n>`, plus the matching MCP tool.
  Retrieves a PR's changed files as a unified diff rather than only the file list.
- **`powerplatform` / `powerplatform-core`: environment-wide plugin step inventory.** New
  `mcp-pp-cli plugin steps` with `--no-include-disabled` and `-m <n>`, plus the matching MCP tool.
  The implementation (`PluginService.getAllPluginSteps`) lives in `powerplatform-core`; the
  `powerplatform` package wires up the CLI command and the tool.
- **`log-analytics`: structured JSON for `investigate-app`.** `mcp-loganalytics-cli query
  investigate-app <resourceId>` gains `-f json`. Formatting logic moved out of the command and the
  tool into a shared `log-analytics-service` plus a `loganalytics-formatters` utility, so the CLI
  and MCP paths now render from one code path instead of two divergent copies.
- **`docs/KNOWN_ISSUES.md` added** — records two confirmed PII-pipeline defects that are
  deliberately not fixed in this wave, and one previously-reported claim that did not survive
  verification. See [Known Issues](#known-issues).

## Testing

**Verified:**

- Full clean build (`npm run build:release`) green — 28 stale `tsconfig.tsbuildinfo` files purged
  first. Every published package emits `.d.ts` (`powerplatform-core` 50, `powerplatform` 32,
  `azure-devops` 71, `log-analytics` 20, `meta` 3).
- Unit suites green across all 13 test-bearing packages: **735 tests**, run against the clean build.
- All three ports ship tests: `pull-request-diff.test.ts`, `log-analytics-service.test.ts`,
  `loganalytics-formatters.test.ts`, `PluginService.getAllPluginSteps.test.ts`.

**Not verified — read this before trusting the new commands:**

- **No live Azure DevOps organisation, Power Platform environment or Log Analytics workspace was
  available.** None of the three new commands has been executed against a real backend. Command
  names, flags, enum values and grammar were read from source; runtime behaviour was not exercised.
  Treat this beta as "compiles and unit-tests pass", not "verified working end-to-end".

## Known Issues

Two confirmed defects in the shared PII pipeline, carried forward rather than fixed — full detail in
[`docs/KNOWN_ISSUES.md`](../KNOWN_ISSUES.md):

- `createPiiPipelineFromEnv` **discards its options argument**. The parameter is declared `_options`
  and the body only calls `loadPiiConfig()`. Four call sites pass `{ environmentIdentifier: … }`
  into nothing.
- The "environment looks unprotected" warning is **dead code**. `checkEnvironmentLooksUnprotected`
  has zero call sites, and `MCP_ENVIRONMENT_TYPE` is read by no production code path — its only
  non-test occurrence is inside that dead function's own message string.

Neither is introduced by this beta; both predate it.
