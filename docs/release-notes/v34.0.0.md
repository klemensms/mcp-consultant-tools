## Overview

A focused fix wave addressing three GitHub issues: silent data omission in PowerPlatform picklist metadata, silent time-window clipping in Log Analytics queries, and wiki hierarchy enumeration in Azure DevOps. Plus release-pipeline hardening against stale incremental builds. No breaking changes — drop-in upgrade.

## Highlights

- **PowerPlatform `get-entity-attribute` returns picklist option values again** — a type-check bug meant option values were never fetched for any picklist; failures were also swallowed silently. Both fixed, with automatic fallback and an explicit warning when option lookup genuinely fails. ([#issue context](https://github.com/klemensms/mcp-consultant-tools/issues))
- **Log Analytics queries no longer silently clip `ago()` windows** — a KQL query asking for `ago(30d)` previously searched only the last hour under the `PT1H` default timespan. The timespan is now derived from the query itself, and any clipping is reported. ([#1](https://github.com/klemensms/mcp-consultant-tools/issues/1))
- **Wiki trees are now enumerable** — new `get-wiki-tree` tool and `recursionLevel` parameter on `get-wiki-page`; `subPages` actually populates. ([#2](https://github.com/klemensms/mcp-consultant-tools/issues/2))

## 🚀 New Features

### azure-devops: wiki sub-page enumeration ([#2](https://github.com/klemensms/mcp-consultant-tools/issues/2))

- `get-wiki-page` (path and page-id lookup) gains an optional `recursionLevel` parameter (`none` | `oneLevel` | `full`) passed through to the ADO REST call. `subPages` is included in the response only when recursion is requested; the default response carries a `subPagesNote` instead of a misleading always-empty array.
- New `get-wiki-tree` tool (CLI: `mcp-ado-cli wiki tree`) returns the page hierarchy (paths, gitItemPath, URLs, `pageCount`) under any path without pulling page bodies — full-wiki enumeration in a single call. Note: the by-path ADO endpoint does not return numeric page ids, so tree nodes are path-keyed.
- CLI parity: `wiki get --recursion-level`, new `wiki tree` command.

## ✨ Enhancements / Functional Improvements

### log-analytics: timespan transparency ([#1](https://github.com/klemensms/mcp-consultant-tools/issues/1))

- Every query response now echoes `effectiveTimespan` (the timespan actually sent to the API). Markdown output and the CLI summary line surface it too.
- When an explicitly-passed timespan is narrower than the KQL's own `ago()` filter, the response carries a `timespanWarning` naming the clip — intentional clipping still works, it's just no longer silent.

## 🐛 Bug Fixes

### powerplatform-core: `get-entity-attribute` silently omitted picklist option values

- The picklist-type check compared `@odata.type` against values without the leading `#` Dataverse actually returns, so the OptionSet expansion was never attempted for any Picklist/Status/State attribute — option values were always missing.
- When the `$expand=OptionSet` request failed, the error was swallowed and the attribute returned with no options and no warning.
- Fixed: the type check now matches; expansion failure (or an empty expansion, as with global picklists) falls back to the attribute-scoped `OptionSet` and `GlobalOptionSet` navigation-property reads; if everything fails the response carries an explicit `optionSetWarning` instead of silence. Affects `powerplatform`, `powerplatform-customization`, and `powerplatform-data` (all surface this tool). Success-path response shape unchanged.

### log-analytics: `PT1H` default silently capped KQL `ago()` windows ([#1](https://github.com/klemensms/mcp-consultant-tools/issues/1))

- The Azure Monitor Logs API treats the request-level timespan as the outer bound on a query. The `PT1H` default meant `... | where TimeGenerated > ago(30d)` searched one hour, returning misleadingly empty results.
- Fixed: with no explicit timespan, the timespan is derived from the widest `ago()` in the KQL (`ago(30d)` → `P30D`); `PT1H` applies only when the KQL contains no `ago()`. An explicitly-passed timespan is always respected verbatim. The CLI `query execute` command dropped its hardcoded `PT1H` default so derivation applies there too.

## 🧪 Testing & Quality Assurance

- vitest test infrastructure added to `powerplatform-core` (5 tests), `log-analytics` (13 tests), and `azure-devops` wiki service (5 tests) — covering the fixed paths: option-set fallback/warning, timespan derivation/clipping warnings, and recursionLevel pass-through.
- PowerPlatform fix verified live against the dedicated test environment; wiki enumeration verified live read-only against a real 329-page project wiki.

## 🛠 DevOps, Pipelines & Infrastructure

- **Mandatory clean build before publish** ([#3](https://github.com/klemensms/mcp-consultant-tools/issues/3)): new root script `npm run build:release` (purges all `build/` output and `*.tsbuildinfo` before compiling) is now a required step in both release workflows. Guards against the stale-incremental-build class of incidents (v33.0.0 of `powerplatform` shipped briefly without type declarations this way).
- **Tarball `.d.ts` gate**: `scripts/scan-tarball.sh` now fails if a package that declares `types` in its `package.json` ships zero `.d.ts` files.
