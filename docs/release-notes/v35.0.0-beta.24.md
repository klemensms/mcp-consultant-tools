# Release Notes: v35.0.0-beta.24

**Date:** 2026-09-30
**Branch:** `release/35.0`
**Status:** Local testing

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

The signed-in-as-you Microsoft 365 servers reach the beta channel. **`outlook` is new** (31 tools: mail, drafts, categories, send, delete and calendar, each write group behind its own off-by-default switch), **`sharepoint` gains a sign-in mode and in-place content editing** (16-22 tools to 39), and **`teams` gains three tools** (26 to 29). `m365-core` is the new internal library the delegated SharePoint mode and Outlook share for device-code sign-in and the encrypted token cache; it publishes because both depend on it. `meta` moves its Teams and SharePoint pins. `outlook` is not bundled into `meta`.

No breaking change. Every new tool is additive, every new write is off by default, and SharePoint in app-only mode (a client secret configured) behaves as before. No new scope is requested at sign-in by `teams`: the files permission its attachment download uses is deliberately left out of the device-code scope list, so a registration without it loses only that one tool.

## Changes Implemented

- **`feat(m365-core)`** (`00c9da7`). Shared device-code auth for delegated Graph servers: start with background completion, silent refresh, status with granted scopes, logout, an AES-256-GCM MSAL cache with one file per server, a display-only `scp` decoder and off-by-default switches. Ported from `teams`, which is unchanged by it. Also carries the save-to-disk helper used by SharePoint and Outlook downloads.
- **`feat(sharepoint)`: sign-in mode** (`a2cb6e5`, `a7bf682`). No client secret, or `SHAREPOINT_AUTH_MODE=device-code`, signs in as the user; sites become optional and any `siteId` also accepts a full site URL. New `spo-authenticate`, `spo-auth-status`, `spo-logout`; a 403 names the missing permission. Your own OneDrive is readable in this mode.
- **`feat(sharepoint)`: search, links and downloads** (`a773014`). `spo-search-files` (Microsoft Search over every file the user can open), `spo-resolve-link` (any SharePoint or OneDrive URL or sharing link to a drive item), `spo-find-sites`; `spo-download-file` gains `saveToDisk` and `convertToPdf`.
- **`feat(sharepoint)`: content read and edit in place** (`1b432ba`, `f0ec717`, `2504569`, `06f1155`, `c40a352`, `b19f4f1`). Text files, Excel ranges (read and write on the server), Word as anchored Markdown with in-place edits, PowerPoint slides and notes with text replacement, blank Office and text file creation, and upload of a local file by path. Reads governed by `SHAREPOINT_CONTENT_READ`, writes by `SHAREPOINT_CONTENT_WRITE` (default `none`).
- **`fix(sharepoint)`** (`8d8bfe3`, `c2fb443`, `a642545`). Drive root addressed as `/root`; upload conflict behaviour sent as a query parameter rather than a header; search fixture replaced with a live delegated capture.
- **`feat(outlook)`: new server** (`eed659b` and earlier). Mail read, list, search, get, conversation and attachment download; drafts, reply, forward, update and attach (`OUTLOOK_ENABLE_DRAFTS`, following `OUTLOOK_ENABLE_WRITE` while unset); mark read, move, flag (`OUTLOOK_ENABLE_WRITE`); send (`OUTLOOK_ENABLE_SEND`); delete to Deleted Items only (`OUTLOOK_ENABLE_DELETE`). Draft attachments by SharePoint or OneDrive link (`1d171ed`).
- **`feat(outlook)`: calendar** (`a537b1d` to `f337995`, `7e697c2`). Five reads (calendars, events, one event, free/busy, meeting times) and four changes (create, update, cancel, respond, including a proposed new time). Switches follow what a call does: own calendar with nobody notified, anyone notified, delegate calendars, colleagues' shared calendars. Automatic recording optional and off by default.
- **`feat(outlook)`: categories** (`be0b7a2`). Every message summary carries its categories; `mail-list-categories` reads the mailbox's defined categories; `mail-set-categories` adds and removes named categories, reading and merging the current list so unnamed categories are kept. New switch `OUTLOOK_ENABLE_CATEGORIES`, independent of write.
- **`feat(teams)`** (`86dade4`). `download-message-attachments` (inline images and file attachments), `send-group-message` (new or existing group chat) and `add-chat-member`, with CLI commands.
- **`fix(sharepoint,outlook)`: honour the global `--json` flag** (`c37b6ba`).
- **`fix(deps)`: `@modelcontextprotocol/sdk` raised to the patched release** (`cb05ecb`) and `vitest`/`vite` dev bumps (`f9df530`). These reach users only in the packages published in this iteration; the other packages carry them from their next publish.

## Testing

- Unit suites green: `outlook` 177, `sharepoint` 140, `teams` 201, `m365-core` 56. Clean release build before publish.
- **Live, from the local build, against a real tenant:** SharePoint's 39 tools listed and a Word read performed; Outlook drafts-only mode and auth status; the Outlook calendar (create, move, cancel, invite, free/busy, shared read, accept, tentative with a proposed time); an Outlook categories add-and-remove round trip that left the message exactly as it started; and the three new Teams tools, confirmed working by the maintainer.
- **Not verified live:** Outlook send and delete, delegate calendars and automatic recording; SharePoint content writes beyond what the plan's live task covered; Teams attachment download on a registration without a files permission (the degraded path is unit-tested only).

## Known Issues

- **`teams` cannot send a file.** Download works; sending needs an upload to the chat's folder plus a reference attachment. Recorded in `docs/KNOWN_ISSUES.md`.
- **`sharepoint` and `teams` still pin `core` at `33.0.0`** (see the root `CLAUDE.md`); unchanged by this iteration.
