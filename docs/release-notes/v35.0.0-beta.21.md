# Release Notes: v35.0.0-beta.21

**Date:** 2026-08-31
**Branch:** `release/35.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

Single-defect iteration in the Teams inbound renderer, plus the related gap beside it. **Reading a Teams message discarded every link URL in it**, and every attachment arrived as an identical unlabelled marker. Both are silent losses: the message reads as ordinary prose afterwards, so nothing signals that anything went missing, and the reader has to open Teams to recover what the tool was supposed to hand them.

`teams` and `meta` only. No config change, no new scope, no tool signature change.

## Changes Implemented

- **Links keep their URLs.** `htmlToText` flattened Graph's message HTML by reading `document.body.textContent`, which keeps an anchor's label and throws its `href` away. A message reading `Licensing Documents Its all here.`, where the first two words were a hyperlink, came back with no URL anywhere in the response. Anchors are now rendered as markdown, `[label](href)`, in the same pass that already rewrote images, emoji and mentions.
  - An anchor Teams auto-linked from a pasted URL is labelled with the URL itself, so it renders as the bare URL rather than as `[https://x](https://x)`. The comparison sets aside a `mailto:` or `tel:` scheme and a trailing slash, so `<a href="mailto:jdoe@example.com">jdoe@example.com</a>` renders as the address alone.
  - An anchor with no `href` renders as its label; an anchor with no label renders as its URL. An anchor whose label merely looks like a URL while pointing somewhere else still renders as a markdown link, so the real target is never hidden behind a plausible-looking label.

- **Attachments say what they are.** Graph's `attachments[]` array was never read on inbound. The message body carries only an `<attachment id="...">` placeholder, and everything a reader needs - the file name, the URL a preview card points at, the message a reply is quoting - lives in that sibling array, so every attachment of every kind rendered as an identical `[attachment]`. The array is now joined onto the placeholders by id:

  | Renders as | What it is |
  |---|---|
  | `[attachment: Report.docx - https://…]` | A file, or a link-preview card Teams generated from a URL in the message |
  | `[quoted reply from Jane Doe: the quoted text]` | Someone replied quoting an earlier message |
  | `[attachment: some/content-type]`, or `[attachment]` | Graph sent something carrying no name and no URL |

  **The quoted text was previously unrecoverable.** It is not in the message body at all, so a quoted reply came back as a bare marker with its subject missing, and which earlier message it answered had to be guessed from position and chronology. Graph does carry it, in the attachment's `content`, and it is now read. The preview is clipped at 200 characters.

- **An attachment Graph sends with no placeholder in the body is appended rather than dropped**, so the failure mode this function exists to fix does not recur one level up.

- **Both call sites are wired**, `toMessageInfo` in `message-service.ts` and `toSearchHit` in `search-service.ts`, so chat reads, channel reads, thread replies and search hits all benefit from one change.

- **Output-shape note, not a config change.** The `text` field of a message now contains markdown links where it contained bare labels, and named attachment lines where it contained `[attachment]`. Anything matching on the literal string `[attachment]`, or assuming link text is plain prose, sees different output. No tool signature, parameter or environment variable changes.

## Testing

15 new unit tests in `packages/teams/src/__tests__/message-content.test.ts`, covering both renderers and their edge cases. Package suite **161 passing**, typecheck clean, clean build green.

**Verified live against a real Teams tenant**, end to end through the built MCP server rather than in unit tests alone, on all four paths:

- A labelled hyperlink returns `[Sample Documents](https://example.com/faqs/122)`; the same message on beta.10 returned `Sample Documents` with no URL.
- A pasted bare URL is unchanged, confirming the auto-link case produces no markdown noise.
- A file attachment returns its filename and its SharePoint URL.
- A quoted reply returns the quoted message's sender and text.

Every fixture in the new tests is a shape captured from a live Graph payload rather than taken from documentation. The raw payloads were read with a throwaway script calling the package's own Graph client, because every MCP tool returns already-rendered text and the payload the renderer consumes is otherwise invisible.

## Known Issues

None found in this iteration. The renderer still marks an inline image as `[image: alt]` and does not resolve its Graph `hostedContents` URL, which remains deliberate - that URL needs an authenticated fetch and is useless to a reader.
