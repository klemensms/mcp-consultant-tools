# Release Notes: v35.0.0-beta.28

**Date:** not yet published
**Branch:** `release/35.0`
**Status:** In progress

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

1. **Teams messages can carry files.** The five send tools take an optional `attachments` list of local paths.
2. **Teams reads show reactions.** Each message with emoji reactions gets a `Reactions:` line saying who reacted with what and when.

No breaking changes: the parameter is optional and a send without it builds the same request as before, and a message with no reactions renders as before.

## Changes Implemented

- **`feat(teams): send local files with a message`**. `attachments?: string[]` (at most 10) on `send-channel-message`, `reply-to-message`, `send-chat-message`, `send-direct-message` and `send-group-message`; CLI `-a, --attach <paths...>` on the matching commands.
  - Chats: upload to the sender's OneDrive `Microsoft Teams Chat Files` folder, then share each file read-only with the other chat members (no invitation email).
  - Channels: upload to the channel's files folder; no sharing step.
  - The message carries `<attachment id="{eTag GUID}">` and a `reference` entry, so the file arrives on the same message.
  - Every path is checked by the shared local-file guard before anything is created, uploaded or sent; one refused path stops the whole send.
  - Uploads use an upload session with `conflictBehavior: rename`; bytes go to the pre-authenticated upload URL with no token.
  - The result lists each file with its link. A failed upload posts nothing and names the files permission on a 401/403.
  - Needs `Files.ReadWrite`, `Files.ReadWrite.All` or `Sites.ReadWrite.All` on the registration. Not requested at sign-in.
  - New `src/services/outbound-attachments.ts` and `src/local-file-guard.ts`; 53 tests in `outbound-attachments.test.ts` across all five paths.
- **`feat(teams): show message reactions on reads`**. `get-chat-messages`, `get-channel-messages`, `get-message-replies` and `get-channel-messages-delta` render `Reactions: 👍 Like by Jane Doe 13:17` under a message that has reactions; `MessageInfo.reactions` carries emoji, name, user id, user name and time, so the CLI's JSON output has them too.
  - Graph v1.0 returns `reactions` on the normal list call; no new scope.
  - Graph sends the reacting user's id only, so names come from authors in the same read, then one `GET /users/{id}` per unknown id (`User.ReadBasic.All`). A failed lookup shows `by unknown user`.
  - 7 tests: `services/__tests__/message-reactions.test.ts` (fixture copied from the live payload) and three in `format-messages.test.ts`.

## Verified

- Unit: 257 tests pass in `packages/teams`; typecheck and build clean.
- Reactions, live and read-only: `get-chat-messages` on a real one-to-one chat rendered `Reactions: 👍 Like by <user> 13:17` on the reacted message; 269 tests pass.
- Live, read-only: a current token on a registration consented `Sites.ReadWrite.All` carries the scope and can read the `Microsoft Teams Chat Files` folder.

## Not verified

- A live send on each surface: that Graph and the Teams client accept the message shape, and that a recipient opens the file without a request-access step.
- Reactions on channel messages and replies against a live channel (unit tests only), and how Graph reports a custom emoji.
