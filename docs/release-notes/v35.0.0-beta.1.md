# Release Notes: v35.0.0-beta.1

**Date:** 2026-06-16
**Branch:** `release/35.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

First v35 beta. A security-hardening wave closing the four items deferred from the v34 audit (the maintainer owns the fifth, npm-token scoping). No breaking changes; no new required configuration.

## Changes Implemented

- **(Item 2) MCP tool safety annotations across all 21 integration packages** — 589 tools annotated with `readOnlyHint` / `destructiveHint` / `openWorldHint`. Classified by handler behaviour, not name prefix:
  - Pure reads → `{ readOnlyHint: true, openWorldHint: true }` (or `{ readOnlyHint: true }` for local-only reads such as config/template getters).
  - Destructive → `{ readOnlyHint: false, destructiveHint: true, openWorldHint: true }` — includes `delete-*`, `drop-*`, `deactivate-*`, `disassociate-*`, access revocations (`revoke-*`, `unassign-*`, `remove-pr-*`), queue/table purges, `cancel-build`, `disable-agent`, `complete-pull-request` (merges + deletes source branch), and arbitrary executors (`sql-execute-unrestricted`/`-sproc`, PP `execute-action`) where the operation can destroy data.
  - Mutating non-destructive → `{ readOnlyHint: false, destructiveHint: false, openWorldHint: true }` — `create-*`/`update-*`/`set-*`/`add-*` and similar writes that don't delete.
  - Behavioural catches where name ≠ behaviour: `document-automation`/`document-workflow-safe` write a description (→ mutating); `sync-*-to-file`/`create-*-file`/`download-*` write only local files (→ read); `sql-execute-query` is SELECT-validated (→ read); `render-visualization` is closed-world (→ read, no `openWorldHint`).
- **(Item 1a) Dependency-vulnerability surfacing in CI** — added `.github/dependabot.yml` (npm workspaces + github-actions, grouped) and an `npm audit --audit-level=high` job in `build.yml`. CI-only; no package changes, no version bumps.
- **(Item 3) `rest-api` OpenAPI-spec fetch bounded** — `doFetchOpenApiSpec` gained an `http(s)`-only scheme guard, `redirect: "error"`, and a 10 MB size cap (Content-Length pre-check + post-read byte check), mirroring the main request path's v34 hardening.
- **(Item 4) `rest-api` SSL-verify toggle hardened** — removed the dead `https.Agent` (ignored by native `fetch`, so the toggle was a silent no-op with TLS always verified). The server no longer disables TLS itself; `REST_ENABLE_SSL_VERIFY=false` now emits a loud security warning directing the operator to set `NODE_TLS_REJECT_UNAUTHORIZED` themselves if required.
- **Build fix** — added `todoist` to the root `tsconfig.json` project references so `tsc --build` (and the clean release build) include it.
