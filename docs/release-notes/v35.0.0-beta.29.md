# Release Notes: v35.0.0-beta.29

**Date:** 2026-10-15
**Branch:** `release/35.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

1. **Teams reaction names are looked up more carefully.** Fixes from an independent review of the beta.28 reactions change.
2. **Dataverse names and IDs are checked before a request is built.** The data and metadata tools refuse a table, column, navigation property or option set name that is not a plain name, a record ID that is not a GUID, and a `query-records` row limit that is not a whole number of 1 or more.
3. **Servers and CLIs report their own version under npx.** `core` no longer reads a version from the `package.json` above the launch script, which under npx could be the consumer project's.

4. **Local tests for the Dataverse servers need no live system.** The repo's MCP local tester runs them against a fake Dataverse on this machine by default and reports PASS or FAIL as text.

5. **Sign-ins are kept in the OS keychain.** The PowerPlatform, SharePoint and Outlook servers store their cached sign-in in the macOS Keychain, Windows data protection or the Linux Secret Service instead of an encrypted file whose key could be worked out from the machine name. **Everyone signs in once after upgrading.** Where no keychain is available, the sign-in is kept in memory and asked for again at each server start: this includes WSL, containers and SSH sessions on Linux without a Secret Service, which until now kept their sign-in across restarts.

6. **Dataverse sign-in and counts are more robust.** The full sign-in address is printed, sign-in keeps waiting if the browser cannot open, a second account is no longer swapped in silently during a session, many-to-many counts are correct, a failed metadata lookup is reported as itself instead of "not found", counts use UK number formatting, and a read that hangs fails after two minutes (writes get thirty, since solution, publish and table changes run long).

7. **Record counts are live.** `count-records` without a filter now counts live, so the number is current and includes only records you can read. Only when more than 50,000 records you can read are in the table does it fall back to Dataverse's stored count, labelled as the whole table, not limited to your access, up to 24 hours old.

No breaking changes for valid input. `query-records` with `maxRecords: 0` is now refused: the MCP tool used to turn it into 50 rows, and the CLI (`-m 0`) returned no rows.

## Changes Implemented

- **`fix(teams): bound and harden reaction name lookups`**.
  - At most 50 `/users/{id}` lookups per read, 5 at a time, each with a 10-second timeout, so a first channel delta with many reactors cannot trigger Graph throttling or hang the read. Names beyond the cap show as `unknown user`, and the cap and any failed lookups are logged to stderr.
  - An author Graph sent without a name (rendered "Unknown" or "System") no longer stops the lookup of that person's name when they also reacted.
  - The formatter test no longer depends on the machine's locale.
  - Lookups stop starting after 15 seconds in total for one read; a timed-out call cannot be cancelled, so the 5-at-once cap is best-effort.
  - New tests: channel delta reactions, an app reactor with no user, a nameless author, the lookup cap, peak concurrency, a lookup that never answers.

- **`fix(powerplatform): check names and IDs before they reach a request address`**.
  - New `powerplatform-core/src/utils/validate.ts`: plain names must match `^[A-Za-z_][A-Za-z0-9_]*$`, record IDs must be GUIDs, action names may be dot-qualified, row limits must be whole numbers of 1 or more.
  - Called at every `DataService` and `MetadataService` entry point that puts a value into the address or a quoted OData literal: get, query (table, each `select` column, `maxRecords`), create, update, delete, associate, disassociate, bound and unbound actions, counts, lookup navigation properties (including `@odata.bind` keys on create and update), entity metadata, attributes, attribute type, relationships, global option set name and prefix.
  - Main gain: PII redaction keys on the table name and the select list, so a table value carrying its own query string could get past it. It now cannot reach a request.
  - `count-records` batch reports a bad name against that entry only.
  - `select` accepts `["a,b"]` as well as `["a","b"]` (the CLI's `-s a,b` arrives that way); the entry is split before the check, so PII exclusions now see each column.
  - `$filter` and FetchXML stay unchecked (encoded, expressions by design). The customization services' own interpolations are not checked (developer input, deferred); the customization tools that call the shared metadata reads are checked through them.
  - `query-records` schema now `int().min(1)`; the CLI parses `-m` with `Number`, so `2.5` is refused rather than truncated to 2.
  - Duplicated GUID checks in `DataService` replaced by the shared helper with the same GUID error text; an empty table or navigation property name now reads "Invalid table name" instead of "cannot be empty".
  - 50 tests: `utils/__tests__/validate.test.ts`, `services/__tests__/DataService.validation.test.ts`.

- **`fix(core): report the version each package passes in`**.
  - `createMcpServer` and `createCliProgram` used `resolvePackageVersion`, which walked up from `process.argv[1]` to the nearest `package.json`. Under npx that is a bin shim in the consumer's tree, so a server could report the consumer project's version in the MCP initialize handshake.
  - Both now use the `version` the entrypoint passes, which every entrypoint already reads from its own `package.json` (guarded by `meta`'s `entrypoint-versions.test.ts`). `resolve-version.ts` is removed; it was not exported.
  - ⚠️ **Release step:** users get this only once `core` is published at a new version (beta.3) and the 9 packages that call these helpers and pin `core` exactly are repinned to it: `azure-defender`, `azure-devops`, `azure-management`, `code-review`, `meta`, `outlook`, `powerplatform`, `powerplatform-customization`, `powerplatform-data`. The 18 packages pinned to `core` 33.0.0 or 34.1.0 keep the old behaviour until their pin is bumped (tracked in `docs/KNOWN_ISSUES.md`).
  - 2 tests in `core/src/helpers/__tests__/reported-version.test.ts`, through a real initialize handshake.

- **`feat(test): fake-service mode for the local MCP tester`** (repo tooling, plus one test switch in `powerplatform-core`).
  - `.claude/templates/fake-dataverse.mjs`: a fake Dataverse Web API on 127.0.0.1 with `accounts` and `contacts`, planted personal values on contacts, and a log of every request.
  - `.claude/templates/mcp-test-runner.mjs`: `MCP_TEST_MODE` (`fake` by default for `powerplatform*` packages, `live` otherwise); fails on an unexpected write or a planted value in the output (PII protection is turned on in fake mode); `MCP_TEST_EXPECT_ERROR` for refusal tests, `MCP_TEST_EXPECT_TOOLS` for the tool list, `MCP_TEST_ALLOW_WRITES`, `MCP_TEST_PII=off`, `MCP_TEST_EXPECT_NO_REQUESTS`; also fails on a request without the fake token and on any 404 or 500 from the fake, and refuses to start if the server's `powerplatform-core` build has no fake-service switch (it would otherwise fall back to a real sign-in); last line `[RESULT] PASS` or `[RESULT] FAIL` on every exit path.
  - `powerplatform-core`: `MCP_POWERPLATFORM_FAKE_SERVICE=1` makes `createAuthProvider` return a fixed fake token. It refuses to start unless `POWERPLATFORM_URL` is on this machine and refuses any resource other than that URL, so the token can never reach a real service. Off unless the variable is exactly `1`.
  - `mcp-local-tester` agent: no closing dialog; the verdict is its final message. Env table corrected to the `POWERPLATFORM_*` names the servers read. The test command's `get-entity-metadata` example used `entityLogicalName`; the tool takes `entityName`.
  - 4 tests: `powerplatform-core/src/auth/__tests__/fake-service-auth.test.ts`.

- **`fix(auth): keep the token cache in the OS keychain`**.
  - `powerplatform-core/src/auth/token-cache.ts` and `m365-core/src/token-cache.ts` (mirrored copies) now use `@azure/msal-node-extensions` 1.5.24 (matches msal-node 3.8.1; Node 16+): keychain service `mcp-consultant-tools`, account `powerplatform-{clientId}` or `{server}-{clientId}`. On macOS and Linux only a timestamp file (`<account>.cache`) and a short-lived lock file stay in `~/.mcp-consultant-tools`; on Windows `<account>.cache` holds the cache encrypted with the data protection API.
  - The old `.enc` file was AES-256-GCM under a key derived from hostname and username with a fixed salt shipped in the package, so anyone with a copy of the file could decrypt it. It is deleted on first use.
  - The library has native parts (keytar, msal-node-runtime), so it is an **optional dependency** loaded on first use: a failed native install, a missing library, no keychain (for example Linux without libsecret) or a token folder that cannot be created each fall back to memory only, with one line on stderr. A missing library is final; a keychain that failed to open (cancelled prompt, locked keychain, two servers checking it at once) is tried again after 30 seconds, once however many calls arrive together. A keychain read or write error is logged and never fails the tool call. Plain-text files on Linux are never used.
  - The library's write lock waits at most 3 seconds (its default was 50), and a lock file whose process has gone, left empty for more than 5 seconds, or older than a minute is removed before each read, so a server killed mid-write cannot stall later sign-ins. `clear()` removes the lock file too.
  - `TokenCache.clear()` and `exists()` are now async; `getCachePath()` describes the location instead of returning a file path. Callers updated (`InteractiveAuth.clearCache`, `DelegatedGraphAuth.getStatus`/`logout`, the `powerplatform --logout` CLI).
  - The `teams` server keeps its own encrypted file: it runs msal-node 2.x, which this library does not support. Deferred.
  - ⚠️ **Release step:** users get this only once `powerplatform-core` and `m365-core` are published at new versions and `powerplatform`, `powerplatform-customization`, `powerplatform-data`, `outlook` and `sharepoint` are repinned to them.
  - ℹ️ **Upgrade note for users:** one sign-in after upgrading. On macOS the first keychain access may show a system prompt for `node`; choose Always Allow.
  - 38 tests: `powerplatform-core/src/auth/__tests__/token-cache.test.ts`, `m365-core/src/__tests__/token-cache.test.ts` (fake keychain injected, so no test touches the real one); `delegated-auth.test.ts` now mocks the cache.

- **`fix(powerplatform): second review items 1 to 5`**.
  - Interactive sign-in (`auth/interactive-auth.ts`): the whole sign-in address is printed (it was cut at 80 characters); a browser that fails to open, including a missing launcher such as `xdg-open`, is logged and the sign-in keeps waiting (it used to end the sign-in, and a missing launcher ended the server); the callback server listens on port 0 and keeps that port (no probe-then-reopen gap); a sign-in code is redeemed once and a repeated callback gets a 400; silent sign-in uses the account signed in last in this server session when the cache holds several (it used whichever came first; after a restart it still starts from the first cached account).
  - Many-to-many counts join the intersect table on Entity1's primary key, read from metadata; the FetchXML used the intersect column on both sides, which is wrong when the column names differ, as on self-referencing relationships.
  - Table, relationship and navigation property lookups: a failed request is reported as itself (for example a 403 or 503) and is not cached, so the next call tries again; a genuine "not found" is still reported and cached. Before, any failure became "not found" for the life of the server. `create-record`/`update-record` with a lookup now fail with the real error instead of sending an unconverted `@odata.bind` key.
  - `count-records` totals use en-GB grouping regardless of the machine's locale.
  - Requests through `PowerPlatformClient` time out: reads (GET) after 2 minutes, writes after 30. Solution import and export, publish, table, relationship and plugin writes can run for minutes, and Dataverse carries on after the client gives up, so a short write timeout would report a failure for a change that happened.
  - `get-lookup-target` reads the target metadata and the binding property separately: a failed binding lookup gets its own warning, and the metadata that was read is kept.
  - The fake Dataverse used by the local tester answers one many-to-many relationship, FetchXML counts and one lookup (contact `parentcustomerid` to account).
  - 18 new tests: `DataService.lookups.test.ts` (7), `interactive-auth.test.ts` (7), `PowerPlatformClient.headers.test.ts` (4).

- **`fix(powerplatform): count live by default, snapshot only over the limit`**.
  - Unfiltered counts use `$apply=aggregate(<primary key> with countdistinct as count)`, the same live path as filtered counts. Before, they came from `RetrieveTotalRecordCount`: up to 24 hours old and counting rows the caller cannot read.
  - Over Dataverse's 50,000-row live limit, an unfiltered count falls back to `RetrieveTotalRecordCount` with `snapshot: true` and the label "over the 50,000 live limit: stored count for the whole table, not limited to your access, up to 24 hours old". This replaces the earlier "snapshot count" label. If that stored count is 50,000 or less it contradicts the live refusal (it can be up to 24 hours old), so the count fails and says the stored figure is out of date; if it cannot be read, the error says the live count was over the limit. A filtered count over the limit still fails with the advice to narrow the filter; any other error, including a timeout, is passed through without falling back.
  - Batch counts send every entry through the same path in chunks of 10, so an unfiltered batch makes one aggregate request per table instead of one combined snapshot request.
  - Tool description updated. 10 new or changed tests in `DataService.countRecords.test.ts`, 2 in `count-labels.test.ts`.

## Not verified

- Throttling behaviour against Graph with more than 50 distinct reactors (unit-tested only).
- PowerPlatform name checks against a live environment with valid names (no Dataverse credentials on the build machine); covered by unit tests that assert the request address.
- Keychain cache on Windows and Linux, and a real browser sign-in landing in the keychain (fake mode bypasses interactive auth); the library is Microsoft's own and the fallback is unit-tested.
- Interactive sign-in changes against a real browser and Entra ID (unit-tested with a real callback server and faked MSAL); the request timeout against a slow live environment.
- The snapshot fallback against a live table over 50,000 records (unit-tested with the recorded Dataverse error text).
- An unfiltered live count on a very large table that times out (2 minutes) or hits a Dataverse SQL timeout before the 50,000 refusal: the error is passed through and there is no fallback, where the old snapshot-only path answered at once.
