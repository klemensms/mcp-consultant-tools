# Release Notes: v35.0.0-beta.2

**Date:** 2026-06-17
**Branch:** `release/35.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

Adds a new **team iteration capacity** domain to `@mcp-consultant-tools/azure-devops-admin`. This iteration touches only `azure-devops-admin` (the feature) and `meta` (which bundles it); all other packages stay at `35.0.0-beta.1`.

## Changes Implemented

- **New `iteration-capacity` service/tools/CLI domain** in `azure-devops-admin`:
  - `get-iteration-capacities` — every team member's capacity (capacity-per-day + days-off) for a sprint, with identity GUID / display name / email.
  - `get-team-days-off` — the team-wide days-off collection for a sprint.
  - `set-team-member-capacity` — set one member's capacity + days-off (full replace). *(gated)*
  - `set-team-capacities-batch` — set many members in one call, one PATCH per member (unlisted members untouched). *(gated)*
  - `set-team-days-off` — set the team-wide days-off (full replace). *(gated)*
- **Single gating flag** `AZUREDEVOPS_ENABLE_ITERATION_CAPACITY_UPSERT` (default `false`) controls all three write tools; read tools are always registered.
- **Identity resolution** — the `member` parameter accepts a GUID, email, or display name; non-GUID values resolve against the team-members API (email match, then display name; ambiguous/unmatched → error listing candidates).
- **CLI parity** — `capacity` command group (alias `cap`): `list`, `set`, `set-batch`, `days-off-list`, `days-off-set`.
- **REST** — team-scoped work API (`{project}/{team}/_apis/work/teamsettings/iterations/{iterationId}/capacities` and `/teamdaysoff`), api-version 7.1, PATCH with `application/json` (not json-patch). `iterationId` is the iteration `identifier` GUID.
- **Tool count** — `azure-devops-admin` 66 → 71 (32 read-only + 29 upsert + 10 delete).
- **Docs** — admin technical + user docs, `.env.example`, package `CLAUDE.md`, README, and a design spec under `docs/superpowers/specs/`.

## Testing

- Full clean monorepo build (`tsc --build`) — zero errors; `meta` and all packages compile.
- Tool-registration + gating verified by booting the built server: flag OFF → 2 read capacity tools only (32 readonly, 0 upsert); flag ON → all 5 (32 readonly + 3 upsert). CLI `capacity --help` lists all 5 subcommands.
- Independent adversarial code review: no critical/major findings; REST shapes, content-types, identity fields, and full-replace/no-data-loss semantics confirmed against the proven REST. Four minor robustness items (CLI numeric/array validation, team-roster `$top` ceiling, all-GUID batch fast-path) fixed.
- **Not verified locally:** live write against a real sprint — needs an ADO env with a `vso.work_write` PAT. The REST shapes were proven by hand before implementation. User to confirm a live `set-team-member-capacity` post-install.
