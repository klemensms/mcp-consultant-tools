# Release Notes: v35.0.0-beta.27

**Date:** 2026-10-06
**Branch:** `release/35.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

Four bodies of work.

1. **`track-email` in `powerplatform-data`** records an Outlook email in Dynamics as an email activity.
2. **Outlook `mail-flag-message` takes a due date and a reminder**, the documented alternative to snooze, which Graph does not offer for mail.
3. **`powerplatform-core` fixes from a security and correctness review of a separate copy of this server**: redirects, fixed headers, error logs, shared sign-in, the sign-in callback, `hasMore` after a trim, and filtered counts.
4. **Hardening**: a stricter local-file guard in three packages, exact dependency pins and a shrinkwrap for the PowerPlatform packages, and a safer publish.

No breaking changes, so this iteration ships no `⚡ Quick upgrade` block. The count label is new output text only; `countRecords` still returns a number.

## Changes Implemented

- **`feat(powerplatform-data): track-email records an Outlook email in Dynamics`** (`f6670da`). New write tool `track-email` and CLI `email track`, behind `POWERPLATFORM_ENABLE_CREATE`. The agent reads the email with the `outlook` server and passes its fields; this server needs no Outlook permission.
  - Keyed on the internet message id (stored as the activity's `messageid`): an already-tracked email is reused and only its Regarding is set, with the previous Regarding reported.
  - Sender and recipients resolve to user, contact, account or lead by email address; unmatched addresses are kept as plain addresses.
  - Regarding accepts any table enabled for activities; the bind name is read from metadata and other tables are refused before any write.
  - Optional attachments from local paths, under the local-file guard, 25 MB each.
  - The activity is closed as Sent or Received; a failure after creation names the activity id.
  - `outlook` `mail-get-message` now returns `internetMessageId` and `sentDateTime`.
  - Logic and tests live in `powerplatform-core` (`EmailTrackingService`).
- **`fix: gate track-email's Regarding change on the update switch, and refuse ~/Library and ~/AppData in file guards`** (`acd015d`). Re-tracking with a new Regarding is an update, so it also needs `POWERPLATFORM_ENABLE_UPDATE=true` and refuses before any write otherwise. The local-file guard in `powerplatform-core`, `outlook` and `sharepoint` now refuses `~/Library` and `~/AppData`.
- **`fix(security): refuse hard-linked files and .ppk/.kdbx in the local-file guards`** (`567628e`). Same three packages.
- **`feat(outlook): follow-up due date and reminder on mail-flag-message`** (`8620a4c`). Optional `dueDateTime`, `startDateTime`, `timeZone` and `reminderDateTime` with flag `flagged`; dates go to Graph as UTC. Start defaults to now; a start without a due date, or after it, is refused. `notFlagged` switches the reminder off and refuses dates. All refusals happen before any request.
- **`fix(outlook): marking a flag complete also switches its reminder off`** (`6c30019`), matching Outlook.
- **`fix(powerplatform-core): no redirects, fixed headers last, path-only error log`** (`ae3e692`). Requests pass `maxRedirects: 0`. Caller headers are applied first and the fixed ones (`Authorization`, `Accept`, OData versions, `Content-Type`) last, matched case-insensitively. The failure log omits the query string.
- **`fix(powerplatform-core): share one browser sign-in between parallel calls`** (`3b08f4c`). Waiting calls repeat the silent lookup for their own resource, so a Power Automate call never receives a Dataverse token. A failed sign-in fails its waiters.
- **`fix(powerplatform-core): sign-in callback answers 404 for other paths`** (`ad0788b`).
- **`fix(powerplatform-core): query-records reports hasMore when the trim drops rows`** (`7405ea8`).
- **`fix(powerplatform): filtered counts filter, and snapshot counts are labelled`** (`6fd5f90`). Filtered counts use `$apply=filter(...)/aggregate(<key> with countdistinct as count)`, with the key read as `PrimaryIdAttribute` from metadata, and a plain message past Dataverse's 50,000-row aggregate limit. Unfiltered counts come from the `RetrieveTotalRecordCount` snapshot, up to 24 hours old, and are labelled as such by `count-records` and the CLI `record count`, in single and batch mode.
- **`fix(powerplatform): pin third-party dependencies to exact versions`** (`81bb730`). Each range is the version the root lockfile already resolved, so nothing installed changes.
- **`build(release): publish PowerPlatform packages with an npm-shrinkwrap.json`** (`45977cc`). `scripts/make-shrinkwrap.sh` generates it at release time for the four PowerPlatform packages; generated files are gitignored.
- **`build(release): publish without scripts, token after build, only pushed release-branch code`** (`8adce8a`). `npm publish --ignore-scripts`, and `scripts/prepublish-check.sh` refuses unless on a release branch, clean and pushed.
