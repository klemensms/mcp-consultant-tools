# Release Notes: v35.0.0-beta.25

**Date:** 2026-10-01
**Branch:** `release/35.0`
**Status:** Local testing

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

Stops agents signing themselves out of Teams, Outlook and SharePoint every hour. A Teams device-code sign-in was ending after an hour and needing a new device code. **The sign-in itself was fine**: the refresh token was stored and a forced silent renewal from it succeeded. The servers' own logs showed agents calling `logout`, then `authenticate`. `auth-status` printed the hourly access-token time as a bare "Expires", an agent read that as the sign-in's deadline and signed out to renew it, and signing out deletes the refresh token. The Teams 403 hint also told agents to log out and sign in again.

No config edit, so no `⚡ Quick upgrade` block. Two tool behaviours change, see Changes.

## Changes Implemented

- **Status no longer shows a bare expiry.** `auth-status` (Teams), `mail-auth-status` (Outlook) and `spo-auth-status` (SharePoint) report `accessTokenExpiresAt` and `renewsAutomatically: true` instead of `expiresAt`, and the message says the sign-in renews itself and must not be signed out to renew. Teams' text output drops its "Expires" line for "Sign-in: renews automatically, no action needed".
- **Logout needs `confirm: true`.** `logout`, `mail-logout` and `spo-logout` refuse without it, saying that signing out is never needed to renew; each CLI's `auth logout` needs `--confirm`. The descriptions say logout deletes the refresh token.
- **The Teams 403 hint no longer says to log out.** It says this is a permissions failure that logging out will not fix, because a silent refresh already picks up newly consented permissions.
- The shared strings live in `m365-core` (`RENEWS_AUTOMATICALLY`, `LOGOUT_WARNING`, `logoutRefusal`), used by Outlook and SharePoint. Teams keeps its own copy, because it does not depend on `m365-core`.

## Testing

- Unit suites: `m365-core` 58, `teams` 204, `outlook` 190, `sharepoint` 141, all green. New tests pin each refusal, each status shape (no `expiresAt` property), and the reworded 403 hint.
- **Live, against the real sign-ins from the local build:** Teams and Outlook status read as described; `logout` and `mail-logout` without confirm, and the Teams CLI `auth logout` without `--confirm`, each refused, and both token cache files were still in place afterwards. A confirmed logout was deliberately not run, because it would sign the maintainer out.
- **Not verified live:** SharePoint (covered by unit tests only); a confirmed logout on any server.

## Upgrade notes

- A caller reading `expiresAt` from an auth-status result now finds `accessTokenExpiresAt`. Nothing in this repo read it.
- A caller that logs out programmatically must now pass `confirm: true` (CLI: `--confirm`).
