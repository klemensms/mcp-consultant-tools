# Release Notes: v35.0.0-beta.12

**Date:** 2026-08-13
**Branch:** `release/35.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

Two things: the **CLI cache convention is now applied across the whole repo** rather than in `teams` alone, and one small `teams` defect from the beta.10 retest is fixed.

The beta.10 retest passed on all four of its fixes — including `list-chats`, which was the one that could have broken outright, since it sends a new `$expand`. **Both `$expand` forms work against Graph**, including the combined `members,lastMessagePreview` that could not be exercised on the build machine.

No new tools, no scope changes, no configuration changes, and nothing changes how any tool is called.

## Changes Implemented

### CLI write commands no longer cache — now across 14 packages

beta.10 fixed this in `teams` and said plainly that every other package still wrote a cache file into whatever directory the command was run from. That is now done properly.

**The rule:** read commands cache to `.context/.mcp-{abbrev}-cache/` as before — an agent greps that JSON instead of re-running the call, which is the entire point. Write commands pass `persist: false` and write nothing at all: no file, and no `.context/` directory created as a side effect.

**146 write commands** across 14 packages: `1password` (9), `azure-b2c` (4), `azure-data-factory` (7), `azure-devops` (26), `azure-devops-admin` (36), `azure-management` (4), `azure-sql` (5), `azure-storage` (22), `fabric` (15), `powerplatform-data` (3), `rest-api` (1), `sharepoint` (6), `teams` (10), `todoist` (8).

**Classification was reviewed, not guessed.** A verb prefix is a starting point and nothing more — six commands with write-sounding names are reads and keep their cache: `run-saved-query` and `run-results` (`azure-devops`), `runs` and `deployments` (`azure-devops-admin`), `runs`, `run-details` and `publishers` (`powerplatform`), `runs` and `run-details` (`powerplatform-data`), `deploy-status` (`powerplatform-customization`). Each was confirmed by reading its own description. The risk is asymmetric — marking a read as no-cache costs a useful cache file, while missing a write leaves today's behaviour — so where a command was ambiguous it was left caching.

**Three packages are deliberately untouched**, because they do not use the shared wrapper:

- `github-enterprise` and `powerplatform-customization` print with `console.log` and **never cache anything**, so there was nothing to fix.
- `sharepoint` has its own `outputResult` implementation. It now honours `persist`, but it still **ignores the global `--no-cache` flag** — that is a separate pre-existing defect, now recorded in the known issues rather than fixed here.

**Nine packages received the wrapper option but are not republished:** `application-insights`, `azure-defender`, `code-review`, `entra-id`, `figma`, `log-analytics`, `message-center`, `powerplatform` and `service-bus` are read-only, so nothing about their behaviour changed and there is nothing to ship. The wrapper is uniform across the repo so a future write command in any of them starts from the right default; it will reach npm whenever those packages next release.

### Bug fix — the CLI accepted an invalid `--type` and let Graph explain it badly

`mcp-teams-cli react-to-* --type nonsense` reached Graph, because an unmapped name has no emoji and produced `{ reactionType: undefined }` on the wire. Graph answered:

```
ReactionType cannot be null or whitespace. (Parameter 'ReactionType')
```

The exit code was already 1, so nothing was broken — but the message points at the wrong thing entirely, telling someone who typed a word that the value was empty. `--type` is now validated in the CLI alongside `--action`, naming the six valid values. The MCP tools were never affected: their zod enum rejects it before the service is reached.

## Testing

**Automated.** All monorepo suites green after the sweep — 812 tests across 14 test-bearing packages, with `azure-devops` up from 59 to 62.

A new `azure-devops/src/cli/__tests__/output.test.ts` mirrors the `teams` one: a read caches, a write writes **neither the file nor the `.context/` directory**, and `--no-cache` is still honoured on reads. `azure-devops` is the repo's reference package for CLI conventions, so one guard there stands for the sweep rather than copying the same test into fourteen packages.

**The sweep itself was verified rather than trusted.** It is a mechanical edit across 62 files, so:

- The first attempt **was reverted entirely.** It matched wrappers too loosely and clobbered `sharepoint`'s bespoke implementation, deleting a `handleCliError` export and breaking the build. The rerun matches the shared wrapper exactly and reports which packages it declined to touch.
- Every read exception was asserted absent from the output afterwards, not just excluded in the input.
- A sample of generated diffs was read by hand in `azure-devops` and `todoist` before the rest were trusted.
- Full clean `build:release` with zero TypeScript errors across all 25 packages.

**Runtime.** `--type nonsense` is rejected by name on the built CLI, before any network call.

**Not verified — needs the work machine.** The `--type` validation and the `teams` half of the sweep are locally verified. The other 13 packages' write commands have not been run against their live services; the change is uniform and type-checked, and the failure mode if a command were misclassified is a missing cache file rather than a broken call.

## Known Issues

- **`sharepoint`'s CLI ignores `--no-cache`.** Its `outputResult` is a bespoke implementation that never reads the global flags, so read commands always write their cache file and there is no way to opt out. Pre-existing, unrelated to this sweep, and not fixed here because honouring the flag means threading `flags` through every call site in that package.
- **Nine read-only packages carry an unreleased wrapper change** — see above. Intentional: they are not republished because their behaviour did not change.
- `auth login`'s exit code on a completed sign-in, the abandoned-device-code path, `mark-chat-read` and `send-adaptive-card` all remain unexercised live, unchanged from beta.10.
- **The Teams package cannot post an @-mention.** `send-channel-message` and `reply-to-message` take text or markdown only, with no `mentions` array, so an agent that can now *read* mentions correctly still cannot write one. Raised during the beta.10 retest as a genuine capability gap rather than a testing inconvenience. Not scoped.
- **No tool can delete a message the agent sent**, so verification runs cannot clean up after themselves. Still unscoped.
- **`list-teams` is still broken on the `latest` tag (`33.0.0`)** for every device-code user. Fixed on the beta channel only.
- 19 sibling CLIs still report hardcoded stale versions. Deferred to its own sweep.
