# Release Notes: v33.0.0-beta.2

**Date:** 2026-06-04
**Branch:** `release/33.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v33.0.0.md`](v33.0.0.md).

## Overview

Single-fix beta. `sync-work-item-from-file` (and the task equivalent `sync-tasks-from-file`) re-wrote HTML body fields on every push — even fields the user never edited — which flipped them to Markdown format and overwrote complex tables with their lossy Markdown rendering. This iteration makes the push detect genuinely-unchanged HTML fields and leave them as the original ADO HTML. Selective bump — only `azure-devops` moves to `33.0.0-beta.2`; `core` stays at `33.0.0-beta.1` and all other packages stay at `32.0.0`.

## Changes Implemented

- **fix(azure-devops): preserve untouched HTML fields on sync push** (`45febc6`). `buildPatchOperations` (`src/sync/markdown-serializer.ts`) and `buildTaskPatchOperations` (`src/sync/task-serializer.ts`) compared the local Markdown body against the raw ADO HTML. Because ADO stores HTML and the local file stores Markdown, the two never matched, so the change-detection skip was effectively disabled for HTML fields (`&& !isHtmlField` / `|| descriptionIsHtml`) and every push re-emitted a `replace` for them. Consequence: editing one field rewrote all HTML body fields, flipping each to Markdown format and — for merged-cell/complex tables — overwriting the faithful ADO HTML with the lossy pulled Markdown. The push now compares the local Markdown against `htmlToMarkdown(currentHtml)` (the same conversion the pull produces), whitespace-normalised, and skips when equal. Genuine edits still differ and still push. Added shared `normalizeMarkdownForCompare` helper to `src/sync/html-converter.ts`.
- **docs(azure-devops): refined the sync "Limitations" note** in `packages/azure-devops/CLAUDE.md` to state that push only writes back fields you actually edited; untouched HTML fields keep their original ADO HTML.

## Version bump

- `azure-devops`: 33.0.0-beta.1 → 33.0.0-beta.2 (its `@mcp-consultant-tools/core` dependency pin stays at 33.0.0-beta.1 — core unchanged).
- All other packages: unchanged (`core` 33.0.0-beta.1; the rest 32.0.0).

## Testing

- One-off TDD assertion script (RED before the fix, GREEN after): 7/7. Covers both builders, both the "untouched HTML field is NOT re-pushed" case and the "genuine edit IS pushed" case, plus the `convertedFields`/`fieldsUpdated` no-longer-falsely-claims assertions.
- End-to-end through a freshly-spawned local `azure-devops` MCP server (`mcp-local-tester`) against a Bug with HTML simple + merged-cell tables: pull → edit only System Info → push → re-fetch. Result: `fieldsUpdated` = `[Microsoft.VSTS.TCM.SystemInfo]` only (Repro Steps absent), ReproSteps HTML preserved byte-for-byte (`<table`/`colspan` intact), revision bumped 1 → 2.
- `tsc` build: pass.

## Known Issues

- ADO Markdown-vs-literal rendering for fields you *do* edit and push is unchanged from prior behaviour (push writes Markdown + sets `multilineFieldsFormat=Markdown`); whether ADO renders that depends on the org's work-item Markdown support. Out of scope for this fix, which only stops *unedited* fields from being touched.
