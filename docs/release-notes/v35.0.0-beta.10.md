# Release Notes: v35.0.0-beta.10

**Date:** 2026-08-13
**Branch:** `release/35.0`
**Status:** Published to beta

> Per-iteration agent-level detail. The user-facing single source of truth is [`v35.0.0.md`](v35.0.0.md).

## Overview

Acts on the beta.8 retest, which passed outright — all six reaction types verified live, and `auth login` verified for the first time. It also surfaced four cosmetic defects, three of them in the **read** path, which is now the main thing this package does. This iteration fixes all four. `teams` and `meta` only; no new tools, no scope changes, no configuration changes.

Nothing here was blocking, and nothing here changes how any tool is called.

## Changes Implemented

### Bug fix — a multi-word mention rendered as one `@` per word

Graph emits **one `<at>` element per word** of a mention, each with its own `mentions[]` entry, all resolving to the same entity. `Jane Doe` therefore arrives as:

```html
<p>Thanks for these <at id="0">Jane</at>&nbsp;<at id="1">Doe</at>&nbsp;- great example!</p>
```

and rendered `@Jane @Doe`. The renderer was correct for a single element; it had simply never been shown what Graph actually emits. Confirmed on both a user mention (two `mentions[]` entries sharing one `mentioned.user.id`) and a channel-tag mention (two entries sharing one `mentioned.conversation.id`, with the tag's display name split across them), reproduced across separate messages.

`htmlToText` now takes the message's `mentions[]` and coalesces runs of `<at>` elements **keyed on the resolved entity id** — `mentioned.user.id`, falling back to `conversation`, `application` and `tag`. Keying on **adjacency** instead would have been the obvious shortcut and is wrong: two different people mentioned back to back are also adjacent, and merging them would invent a name nobody wrote. There is a test for exactly that case. With no `mentions[]` there is nothing to key on, so elements render separately rather than being guessed at.

That fallback creates a trap worth naming: the renderer works perfectly in isolation while the service never passes it anything. `toMessageInfo()` now forwards `message.mentions`, and a **service-level** test asserts a multi-word mention arrives coalesced through a full read — the renderer's own tests would pass with the argument unplumbed.

### Bug fix — emoji vanished from every message body

Teams encodes emoji as `<emoji id="smile" alt="🙂" title="Smile"></emoji>`. The element has no text content and the renderer had no branch for it, so the character was dropped from every message on read — occasionally changing the tone of what a colleague wrote. `htmlToText` now substitutes `alt`, falling back to `title`, and emits nothing when it has neither.

### Bug fix — `list-chats` displayed a field it was not sorting by

The rendered "Last activity" column showed `lastUpdatedDateTime`, which tracks changes to the **chat** (topic, membership) rather than messages in it. Measured live, the two disagree badly: the most recently active chat in the list carried a displayed timestamp **six weeks stale**. The ordering was never wrong — but a reader would conclude that colleague had not been in touch since, and would stop trusting the order too.

The cause is a Graph behaviour worth recording: **`/me/chats` will happily `$orderby=lastMessagePreview/createdDateTime` without returning `lastMessagePreview`.** It is a navigation property and requires `$expand`. So the sort key was never in the response, and the renderer fell back to the wrong field. The request now always expands it (`lastMessagePreview`, or `members,lastMessagePreview` with `includeMembers`), `ChatInfo` gains `lastMessageDateTime`, and the column shows that, falling back to `lastUpdatedDateTime` if absent. `lastUpdatedDateTime` is retained — it is real data — but it is documented as not being activity.

### Bug fix — CLI write commands wrote a cache file into the caller's working directory

Running a reaction command without `--no-cache` created `.context/.mcp-teams-cache/<command>.json` wherever it happened to be invoked — on the test machine, a new `.context/` directory inside a **cloud-synced folder**, which then synced. The contents were innocuous, but a tool that leaves files where it was run is a surprise.

Write commands now persist nothing: `send-message`, `send-card`, `reply-to-message`, `send-chat-message`, `mark-chat-read`, both reaction commands, and `auth login` / `auth logout`. Their payload was only an echo of the arguments, so the file had no value to grep in the first place. **Read commands still cache** — that JSON is the point, since an agent greps it instead of re-running the call, and `.context/` is the documented place for it.

**Scope, stated plainly:** this is fixed in `teams` only. The `outputResult` wrapper is per-package, so every other package's CLI still caches write commands into the caller's cwd. Doing it repo-wide means editing ~20 packages plus a `core` change and its version ripple, which warrants its own wave rather than riding along in a Teams one.

### Consistency — the CLI accepts `--action` as well as `--remove`

The MCP tools take `action: "add" | "remove"`; the CLI took `--remove` and rejected `--action remove` with `error: unknown option '--action'`. Both spellings now work on both reaction commands. `--remove` wins if both are given; an `--action` value that is neither `add` nor `remove` is rejected by name rather than silently treated as "add".

## Testing

**Automated.** 45 tests green (`npm run test --workspace=packages/teams`), up from 31.

- `message-content.test.ts` (new, 9) — mention coalescing for user and channel-tag mentions, the **non**-merge of two different entities standing adjacent, single-element mentions, the no-`mentions[]` fallback, non-merge across intervening words, and the three emoji cases.
- `message-service.test.ts` (+2, now 27) — mentions plumbed end to end through a read; `lastMessagePreview` expanded and mapped separately from `lastUpdatedDateTime`.
- `cli/__tests__/output.test.ts` (new, 3) — a read caches; a write writes **neither the file nor the `.context/` directory**; `--no-cache` still honoured on reads.

**Inversion-checked**, each fix reverted against the new assertions before the suite was trusted: unplumbing `message.mentions` → 1 red; dropping the emoji `alt` substitution → 2 red; ignoring `persist` → 1 red; removing the `lastMessagePreview` expand → 2 red. All green again with the sources restored.

Two of these are deliberately **absence** assertions — no `.context/` directory for a write, and no merge of adjacent-but-different mentions — following the lesson from the `$top` and `reactionType` defects, where every test asserted only what the code already did.

**Runtime.** Clean build; the server registers **16 tools** over real MCP stdio. `--action remove` is accepted on the built CLI, `--action sideways` is rejected with a named error, and both appear in `--help`.

**Not verified — needs the work machine.** No Teams credentials here, so none of this has been run against live Teams. Two items carry real risk and should be checked first:

1. **`list-chats` sends a new `$expand`.** `$expand=lastMessagePreview` and `$expand=members,lastMessagePreview` are both documented as supported, but the *combined* form has not been exercised against Graph. If it is rejected, `list-chats` fails outright rather than degrading — this is the one change in the wave that could break a working tool.
2. **Mention coalescing** was built from captured HTML rather than a live read, so it should be confirmed against a real message containing a multi-word mention, and against a message mentioning two different people in a row.

The emoji fix and the CLI changes are low-risk and locally verified.

## Known Issues

- **`auth login`'s exit code on a completed sign-in is still unconfirmed**, and the abandoned-device-code path remains untested — proving it means sitting out the code's full lifetime, which suits a test that fakes the clock better than a live run.
- **`mark-chat-read` and `send-adaptive-card` remain unexercised live.** The first would clear real unread state in a live chat.
- **All live verification is Graph-confirmed, not client-confirmed.** No agent on the test machine can see the Teams UI, so a disagreement between Graph's stored state and what Teams renders would not be caught.
- **No tool can delete a message the agent sent**, so verification runs cannot clean up after themselves. Still unscoped.
- **Every other package's CLI still caches write commands into the caller's working directory** — see the scope note above.
- **`list-teams` is still broken on the `latest` tag (`33.0.0`)** for every device-code user. Fixed on the beta channel only.
- 19 sibling CLIs still report hardcoded stale versions. Deferred to its own sweep.
