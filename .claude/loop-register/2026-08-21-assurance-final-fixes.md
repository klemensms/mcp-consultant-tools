### ⚑1 · D16's version-regression premise is not supported by the ARM contract
- **Kind:** assumption
- **Hop:** origin · c3edf18
- **State:** open
- **Matters because:** the whole of D16 was recorded as "at `2025-05-04` both
  `implementationEffort` and `userImpact` are optional and absent from every example, while the
  `2020-01-01` examples carry them", and the predecessor chain's ⚑36 built a product trade-off
  on top of it (two calls per invocation, or lose `Critical` severity). Read at the origin hop:
  the `2020-01-01` swagger marks `SecurityAssessmentMetadataProperties.required` as
  `['displayName', 'severity', 'assessmentType']`, so **both fields are optional in the old
  version too**. The only evidence of a version difference is which examples happen to include
  them, and this repo has already been bitten once by treating an autogenerated example as
  evidence. If the premise is wrong, ⚑36's trade-off does not exist and there is nothing to
  arbitrate. Settled by the diagnostic this chain builds, not by more reading.

### ⚑2 · D16's scope refutation was over-stated, and the tenant-scope call has never been made
- **Kind:** assumption
- **Hop:** origin · c3edf18
- **State:** open
- **Matters because:** hop L6 of the predecessor chain refuted "read the catalogue at a
  different scope" on the grounds that the tenant-scope and subscription-scope operations return
  the same `SecurityAssessmentMetadataList` definition. That is true of the **schema** and says
  nothing about whether the service **populates** the two optional fields the same way at both
  scopes. `listAssessmentMetadata` only ever calls the subscription-scoped path
  (`/subscriptions/{id}/providers/Microsoft.Security/assessmentMetadata`), and the spec also
  defines a tenant-scope `AssessmentsMetadata_List` at
  `/providers/Microsoft.Security/assessmentMetadata` which nothing in this package has ever
  called. If tenant scope populates the fields, the fix is one call at a different path with no
  version juggling and no capability trade-off at all.

### ⚑3 · D17 is closed on a specification read, not on live data
- **Kind:** assumption
- **Hop:** origin · c3edf18
- **State:** open
- **Matters because:** the origin hop closed D17's last credential-free candidate by reading the
  current TypeSpec: `ExpandEnum` has exactly two members (`links`, `metadata`), the `list`
  operation accepts no `$expand` at all, and `risk?` is optional on
  `SecurityAssessmentPropertiesBase`. So `$expand` cannot deliver a risk object and no
  request-side change exists. **That is a fact about the API, not about the estate.** The
  remaining explanation, that the measured subscriptions genuinely carried no risk objects and
  no `Critical` findings because Defender CSPM was off, is still unverified and is answered by
  one `defender-list-plans` run per subscription. A hop that writes "D17 is fixed" without that
  distinction is overclaiming.
